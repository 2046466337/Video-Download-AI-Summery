# 万能视频下载站 · 需求分析文档

> 版本：v1.0（MVP 阶段）
> 最后更新：2026-09-22
> 本文档用于沉淀项目背景与需求边界，后续扩展功能时作为 AI 与新成员的上下文参考。

---

## 1. 项目背景

用户有把网络视频保存到本地的真实需求，但现有渠道普遍存在障碍：

| 痛点 | 具体表现 |
| --- | --- |
| 平台不提供下载 | 网页端只能在线播放，没有下载入口 |
| 下载不方便 | 需要装客户端、注册登录、或只能在 App 内"离线缓存"，文件拿不出来 |
| 清晰度受限 | 免费用户被限制在 480P/720P，高清要开会员 |
| 不支持批量 | 一次只能存一个，几十条链接要手动重复几十次 |
| 移动端无解 | 手机浏览器基本没有可用方案，而用户恰恰常在手机上刷到想存的视频 |
| 格式单一 | 想单独提取音频（播客、音乐、课程）没有现成办法 |

## 2. 项目目标

做一个 **打开网页、粘贴链接、选清晰度、点下载** 的全平台视频下载站，电脑和手机都能用，不需要安装任何客户端。

三条产品原则：

1. **零门槛**：首屏就是输入框，不注册也能用，第一次使用不超过 3 次点击完成下载
2. **全平台**：站在 yt-dlp 的肩膀上，覆盖上千个站点，不自己写解析器
3. **可商业化**：免费档满足尝鲜，高价值能力（高清、批量、音频提取、AI 总结）留给付费档

## 3. 目标用户与典型场景

| 用户类型 | 典型场景 |
| --- | --- |
| 内容创作者 | 下载素材做二次创作，需要高清原片和批量能力 |
| 学生 / 自学者 | 保存网课、讲座，离线观看；只想听的场景需要提取 MP3 |
| 普通用户 | 刷到有意思的视频想存到相册，通常在手机上 |
| 研究 / 运营 | 批量归档某个账号或话题下的视频做分析 |

## 4. 功能需求

## 5. 非功能需求

- **性能**：解析响应控制在 5 秒内；下载并发默认限 3，避免带宽被单用户打满
- **可用性**：首屏加载快，交互不超过 3 步完成主流程
- **可维护性**：不修改 yt-dlp 源码，只做薄封装，保证能随时升级上游
- **安全性**：解析接口必须做 SSRF 防护（拒绝内网与回环地址）；文件访问必须通过不可枚举的任务 ID
- **轻量部署**：无外部数据库与中间件，SQLite 单文件 + 本地磁盘即可跑起来

## 6. 商业化设计（为 UI 服务的目标）

| 能力 | 免费版 | Pro 版 |
| --- | --- | --- |
| 最高清晰度 | 720P、1280P | 4K / 原画 |
| 每日下载次数 | 3次 | 不限 |
| 批量下载 | 不支持 | 支持 |
| 音频提取 MP3 | 支持 | 支持 |
| 下载队列 | 普通排队 | 优先队列 |
| AI 视频总结 | 不支持 | 支持 |
| 字幕翻译 | 不支持 | 支持 |

页面需要持续传递"实用价值"而不是堆砌装饰：突出支持平台数量、无需安装、手机可用、高清无损这些用户真正在意的点，并在合适位置为 Pro 能力做铺垫。

## 7. 约束与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 平台反爬策略变化 | 解析失效 | 保持 yt-dlp 可升级，定期 `pip install -U yt-dlp` |
| YouTube 需要 PO Token / cookies | 高清拿不到 | 后续以 Cookies 注入能力解决，包装为 Pro 功能 |
| 服务端带宽与磁盘成本 | 成本失控 | 并发限流 + 文件定时清理 + 付费分档 |
| 版权合规 | 法律风险 | 页面明示免责声明，仅供个人学习与合法备份使用 |
| 大文件下载超时 | 任务失败 | 任务异步化 + 进度可见 + 失败可重试 |

## 8. 验收标准（MVP）

1. 粘贴一条真实视频链接，能在 5 秒内看到标题、封面、时长与清晰度选项
2. 选择任一清晰度后点击下载，进度条能实时推进并正确显示速度与剩余时间
3. 需要合并音视频的清晰度（如 1080P 及以上）下载后播放**有声音**
4. 选择"仅音频"能得到可播放的 MP3
5. 生成的文件通过浏览器点击即可保存到本地，手机浏览器同样可用
6. 在 390px 视口下布局无错位，主流程可完整走通
7. 非法链接、内网地址、解析失败等情况有明确的错误提示而不是白屏
