## 1. 设计原则

1. **不改 yt-dlp 源码，只做薄封装。** 各平台反爬每周都在变，yt-dlp 靠高频发版对抗。一旦 fork，三个月后必然失效。升级方式永远是 `pip install -U yt-dlp`。
2. **下载必须走服务端。** YouTube 1080P 以上是音视频分轨，直链丢给浏览器会没声音；抖音/B 站 CDN 有 Referer 防盗链。手机 Safari 对 JS blob 下载支持很差，必须由后端返回 `Content-Disposition: attachment`。
3. **进度走内存，终态落 SQLite。** 进度 hook 每秒多次回调，写磁盘会把 SQLite 打爆。任务创建/成功/失败才落库。
4. **先可用，再变现。** MVP 不强制登录、不接支付。UI 要持续传递实用价值，并为 Pro 能力预留入口。

## 2. 技术栈

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 后端 | FastAPI + uvicorn | Python 与 yt-dlp 同语言，异步接口 + 线程池即可 |
| 下载引擎 | yt-dlp（库调用） | 覆盖 1000+ 站点，不自己写解析器 |
| 合并/转码 | 本机 FFmpeg | 音视频分轨合并、提取 MP3 |
| 存储 | sqlite3 标准库 | 零外部依赖，一个文件 |
| 前端 | Vue 3 + Vite + TypeScript + Tailwind CSS v4 | 复刻参考站视觉，进度/任务列表好写 |
| 图标 | lucide-vue-next | 线性图标，克制 |
| AI 客户端 | DeepSeek（requests 直调 OpenAI 兼容接口） | 零额外依赖，`stream=True` 走 SSE |
| 思维导图 | markmap-lib + markmap-view | 前端渲染 Markdown 层级结构 |

开发期：Vite `:5173` 把 `/api` 代理到 FastAPI `:8000`。
生产期：`vite build` 后由 FastAPI 托管 `frontend/dist`，单进程部署。

## 4. 核心数据流

```text
用户粘贴 URL
    │
    ▼
POST /api/parse
    │  security.validate_url（协议 + 公网 IP）
    │  ydl_service.parse_video → extract_info(download=False)
    │  build_quality_options 把几十条 format 归档成 4K/2K/1080/720/480/音频
    ▼
前端展示封面 + 清晰度按钮
    │
    ▼
POST /api/downloads
    │  TaskManager 入队（ThreadPoolExecutor，默认并发 3）
    │  yt-dlp download + FFmpeg 合并/转码
    │  progress_hooks / postprocessor_hooks 回写内存
    ▼
前端每 800ms 轮询 GET /api/downloads/{id}
    │
    ▼
成功后 GET /api/files/{id}  → FileResponse + attachment
```

音视频分轨会触发两轮下载。创建任务时把解析阶段估出的 `expected_size` 带上，进度条才不会在第二轮从 0 再走一遍。

## 5. API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | `{status: "ok"}` |
| GET | `/api/stats` | `{total_downloads: n}` 累计成功次数 |
| POST | `/api/parse` | 入参 `{url}`，返回 `VideoInfo` |
| POST | `/api/downloads` | 入参 `{url, option_id, title, quality, platform, expected_size}`，返回 `TaskState` |
| GET | `/api/downloads/{id}` | 进度快照 |
| GET | `/api/files/{id}` | 完成后的附件下载 |
| GET | `/api/summaries/{id}/subtitles?format=srt\|vtt\|md` | 导出原始字幕（attachment 下载，见 8.6） |

`option_id` 约定：

- `video-{height}`：如 `video-1080`，对应 format 选择器 `bestvideo[height<=1080]...+bestaudio`
- `video-best`：站点没给 formats 列表时的兜底
- `audio-mp3`：bestaudio + FFmpegExtractAudio → mp3 192kbps

任务状态机：`queued → running → success | failed`。
阶段文案：排队中 / 下载中 / 合并音视频 / 转换音频 / 已完成 / 失败。

## 6. 清晰度归档规则

yt-dlp 原始 formats 常有 30+ 条，同一高度还有多种编码。直接展示会劝退。

归档口径：

1. 丢掉 mhtml 故事板（它们也带 height，会造出 45P 假档位）
2. 按 height 落入 2160 / 1440 / 1080 / 720 / 480 / 360 / 240
3. 每档挑一条代表：优先 `avc1/h264` + `mp4` + 更高码率（兼容微信和旧手机）
4. 视频轨没有音轨则 `needs_merge=true`，体积加上最佳音轨估算
5. 默认推荐 1080P，没有则推荐最高档
6. 只要有音轨或视频档，就追加「仅音频 MP3」

下载选择器必须和展示口径一致，否则页面上的体积会对不上实际文件。

## 7. 站点适配

`site_profiles.py` 是唯一允许「按站点打补丁」的地方：

- 哔哩哔哩：WAF 会拦截浏览器 UA（412），非浏览器 UA 又拿不到网页里的 `__INITIAL_STATE__`，yt-dlp 官方 extractor 会解析出封面但下不了流。
  适配放在 [`backend/app/bilibili_adapter.py`](../backend/app/bilibili_adapter.py)：走 `view` + `playurl` 公开 API（curl UA + Origin/Referer），CDN 拉流改用浏览器 UA，`try_look=1` 让游客拿到 720/1080。**不要改 yt-dlp 源码。**
- 抖音：`aweme/v1/web/aweme/detail` 从 2026-09 起被 Argus 风控接管，非浏览器请求一律 403 `Blocked by ArgusSecurityPlugin`，yt-dlp 官方 `DouyinIE` 因此失效；且 `douyin.com/jingxuan?modal_id=…` 精选页链接不在其 URL 匹配表里，直接被判「不支持的 URL」。
  适配放在 [`backend/app/douyin_adapter.py`](../backend/app/douyin_adapter.py)：用 Playwright（优先系统 Edge `channel="msedge"`，否则 `playwright install chromium`）打开视频页，由抖音自己的 JS 完成挑战、拿到带签名的 `aweme_detail`，从中取各清晰度的 `douyinvod` 合并流直链（H264 优先，ByteVC1/HEVC 标注兼容性）。直链带时效签名，解析与下载各自重新取一次。**不改 yt-dlp 源码。**
- YouTube / TikTok 等：有 `curl_cffi` 时使用 `ImpersonateTarget.from_str("chrome")`（必须是对象，传字符串会 AssertionError）
- YouTube 在无 cookies 时经常返回 bot check，解析会失败并提示需要登录。这是平台风控，不是封装写错。MVP 公开直链和部分国内站点可跑通；YouTube 高清/稳定解析留给 Cookies 注入（Pro）
- Cookies：把 Netscape 格式的 `cookies.txt` 放到 `backend/data/cookies/<根域名>.txt` 或 `backend/data/cookies.txt`，解析/下载会自动带上。这是后续 Pro 能力（会员内容、需登录高清）的挂钩点，MVP 不做上传 UI。

## 8. AI 视频总结架构

AI 总结与下载完全解耦：独立路由（`summary_routes.py`）、独立任务表（`summary_records`）、独立线程池，下载链路零改动。总结只做「读字幕 → 送 LLM」，不落媒体文件、不占下载目录。

### 8.1 数据流

```text
POST /api/parse 解析成功
    │  自动触发：summary_manager.submit(auto=True) → 返回 summary_task_id
    │  （解析失败不触发；auto 任务字幕提取失败原地重试 1 次）
    ▼
前端拿到 VideoInfo.summary_task_id，自动进入总结流式
    │
    ▼
GET /api/summaries/{id}/stream?module=summary   自动：内容摘要 → 核心要点
GET /api/summaries/{id}/stream?module=subtitle  自动：原始字幕 → 章节大纲
GET /api/summaries/{id}/stream?module=mindmap   点击触发：思维导图
GET /api/summaries/{id}/stream?module=chat      点击触发 + question：AI 问答
```

手动路径（自动任务失败后重试，或旧版本未自动触发）保留「AI 总结」按钮：

```text
用户点「AI 总结」按钮
    │
    ▼
POST /api/summaries                创建手动任务（auto=False，失败即止）
    │  subtitles.extract_subtitles(url) → [{start, end, text}]
    │  transcript_to_text → 带 [MM:SS] 的纯文本
    ▼
GET /api/summaries/{id}/stream?module=...   （同上）
```

### 8.2 字幕提取策略

统一输出 `[{start, end, text}]`（秒）：

| 平台 | 来源 | 说明 |
| --- | --- | --- |
| 哔哩哔哩 | `x/v2/dm/view` | 同时含人工 CC 字幕与 AI 字幕（AI 字幕 `lan` 带 `ai-` 前缀），覆盖仅 AI 字幕的视频；语言优先级：人工中文 > AI 中文 > 首个 |
| 抖音 | 无 | 无公开字幕接口，返回空列表 |
| 其余 | yt-dlp subtitles / automatic_captions | 中文优先，人工字幕优先于自动字幕 |

字幕 URL 兼容 `//` 与 `http://` 前缀，统一转 https。

### 8.3 SSE 流式协议

`GET /api/summaries/{task_id}/stream?module=...`，`Content-Type: text/event-stream`。四个模块各自独立 SSE 流：

| module | phase 序列 | 内容 |
| --- | --- | --- |
| summary | summary → points | 内容摘要 → 核心要点 |
| subtitle | transcript → chapters | 原始字幕 → 章节大纲 |
| mindmap | mindmap | Markdown 层级结构 |
| chat | answer | 问答回答（需 `question` 参数） |

事件类型：

| 事件 | data | 含义 |
| --- | --- | --- |
| phase | `{"phase": "summary"}` | 标记后续 delta 属于哪个子模块 |
| delta | `{"content": "文本分片"}` | 一段文本，前端按收到顺序追加 |
| done | `{}` | 正常结束 |
| error | `{"message": "..."}` | 异常结束，不再有 done |

关键约定：

- **同 Tab 内分片有序**：后端生成器按序 yield，前端 `fetch + ReadableStream` 按序 append，不打乱文本。
- **不同 Tab 独立流**：摘要/字幕是一条自动时序链；思维导图、问答在用户点击后各开新流。
- **缓存**：`summary_manager` 把每个模块的生成结果回填到 `SummaryTask`（`summary_text` / `chapters_text` / `mindmap_md`），重复点击直接返回缓存，不再重复调用 LLM。
- **同步 def + 同步生成器**：Starlette 在线程池中迭代，不阻塞事件循环。

### 8.4 流式生成器

`summarizer.py` 提供与一次性 `summarize()` 并行的流式函数，均 `yield (event, data)`：

- `stream_summary(title, text)` → phase 切 summary / points
- `stream_chapters(title, text)` → 固定「MM:SS 标题｜说明」格式
- `stream_mindmap(title, text, summary)` → Markdown 列表（markmap 可解析）
- `stream_chat(question, title, text, summary)` → 带时间戳的回答

`ai_client.chat_stream()` 是唯一 stream 入口：`stream=True` + `iter_lines` 逐分片 yield，与 `chat_json` / `chat_text` 共用同一套鉴权与错误处理。

### 8.5 前端交互

桌面端左右分栏 4:6（`lg:grid-cols-10`：左 4 右 6），移动端 `grid-cols-1` 上下流式：

- 左栏：视频预览卡（缩略图 + 时长角标 + 清晰度按钮组 + 开始下载 + AI 总结）
- 右栏：四 Tab 面板（总结摘要 / 字幕文本 / 思维导图 / AI 问答，各带图标）

交互约定：

1. **解析成功后自动触发**（v1.2）：`/api/parse` 返回 `summary_task_id`，前端在 `watch(video)` 里检测到非空即调用 `startFromTaskId`，自动进入「总结摘要」并流式生成，无需点击；「AI 总结」按钮保留用于自动任务失败后的手动重试。
2. 点「AI 总结」重置所有 Tab，自动加载「总结摘要 → 字幕文本」两条 SSE 流（`.finally()` 链式，单模块失败继续下一个）。
3. 「思维导图」「AI 问答」不预加载，首次点击才触发 SSE；不点不请求。
4. Tab 无论是否加载完成均可点击切换，不置灰。
5. AI 问答底部输入框 + 发送，回答流式追加。
6. 章节大纲解析兼容 `MM:SS` 与 `[MM:SS]` 两种时间戳格式，点击跳转原视频 `?t=秒`。
7. **双栏等高**（v1.2）：仅「思维导图」「AI 问答」两个 Tab 的内容区 `flex-1` 撑满，使右卡片与左栏主卡片顶端对齐、底端拉齐；左栏 `VideoResult` 结构与样式零改动。

### 8.6 字幕下载导出（v1.2）

`GET /api/summaries/{task_id}/subtitles?format=srt|vtt|md`，读取任务已提取的**原始字幕轴**（`SummaryTask.transcript`，毫秒级时间戳），格式化后以 `Content-Disposition: attachment` 返回，浏览器默认下载弹窗本地保存。

| 关键点 | 说明 |
| --- | --- |
| 数据源 | 直接读 `SummaryTask.transcript`，不重新解析字幕串，保留精确时间戳 |
| 仅原始字幕 | 项目无翻译功能，天然满足「不含翻译字幕」；未来加翻译也不污染此端点 |
| 格式化 | 新增 `subtitle_export.py` 纯函数 `to_srt / to_vtt / to_markdown` + `safe_filename`，不动 `subtitles.py` |
| 文件名 | `《标题》.srt/.vtt/.md`，正文用 RFC 5987 UTF-8 文件名 + ASCII 回退 |
| 前端触发 | `window.location.href = 导出URL`（与视频下载一致，不走 blob） |

### 8.7 思维导图全屏与导出（v1.2）

`MarkmapView.vue` 顶部工具栏新增「全屏」「下载」按钮：

- **全屏**：`rootRef.requestFullscreen()`（`try-catch` 兜底受限环境）；`fullscreenchange` 后 `setTimeout(mm.fit, 200)` 自适应；ESC 或再次点击退出。
- **SVG 导出**：克隆 SVG → 移除根分组缩放 transform → 按 `mm.state.rect`（全图边界）设 `viewBox` → 加白底 `rect` → `width/height=100%`。为支持浏览器内缩放/拖拽，额外把内容包进 `<g id="viewport">` 并内嵌脚本：滚轮以鼠标为锚点缩放（`getScreenCTM().inverse()` 换算），`pointer` 事件拖拽平移。用 `XMLSerializer` 序列化后经 `utils/download.ts` 的 `downloadText` 下载。
- **Markdown 导出**：直接下载 `mindmapMarkdown` 字符串。
- **PDF**：暂未引入（原需求列了 PDF，当前留扩展点，未加 `jspdf` 依赖）。

### 8.8 解析后自动触发与重试（v1.2）

- `POST /api/parse` 成功后调用 `summary_manager.submit(auto=True)`，把 `task.id` 写入 `VideoInfo.summary_task_id`；解析失败（`ParseError`）走原 422/400，不触发。
- `SummaryTask.auto` 标记自动任务；`_run()` 中 **auto 任务字幕提取失败时在同一 taskId 内原地重试 1 次**（共 2 次尝试），2 次都失败才置 `failed`；手动任务失败即止。
- **不补跑存量**：不引入任何历史扫描/批量补跑逻辑，自动触发只内联在新 `/api/parse` 请求上（解析本就不落库，天然满足「仅新上传视频生效」）。
- 遵循开闭原则：`schemas.py` 追加字段、`summary_manager.py` 扩展参数、`routes.py` 在 parse 成功后追加调用，均不改动既有端点行为。

## 9. 安全与运维

- **SSRF**：只允许 http/https；`getaddrinfo` 解析后拒绝私网、回环、链路本地、组播、保留地址。
- **分享文案**：抖音/小红书复制出来是一段话夹着链接，`security.py` 用正则抽出第一个 http(s) URL。
- **文件访问**：只能通过不可枚举的 `task_id`（uuid4 hex）下载，不暴露目录列表。
- **磁盘**：`FILE_TTL_HOURS` 默认 6 小时，cleaner 每 30 分钟扫一次 `data/downloads/`。
- **并发**：`MAX_CONCURRENT_DOWNLOADS` 默认 3，可用环境变量改。
